# Implementation report

Redesign of Somewhere in Mountains, 24 November 2026. Brief: complete redesign, UX
optimisation and QA. Decisions confirmed with Harpreet before starting:

- Keep the **mountain-blue palette** (the brief suggested earthy colours).
- Follow the brief's **structure and button names**, but keep Jenish's specific, personal voice
  instead of generic slogans ("Discover Nepal. Beyond the ordinary." was not used).
- Do everything in phases, committing after each.
- **Leave out** anything that needs facts we don't have (prices, daily itineraries, licence,
  languages, maps) and list them in `BUSINESS_OWNER_CHECKLIST.md`.

## Architecture

- **No framework migration.** Still static HTML/CSS/JS built by `source/build.py`
  (Python 3.9+ and Pillow). Output: `site/`.
- **Single source of truth:** `source/data.py`. Every card, filter value, comparison row,
  finder entry, trip page, form option and JSON-LD block is generated from it. New fields
  per trip in `TRIP_FACTS`: `days`, `diff`, `area`, `first`, `for`, `start`, `end`, `stay`,
  `tags`.
- **Repository layout changed:** the repo root is now `website-final/` (was `website-final/site/`),
  so the source, docs and tests are versioned. `vercel.json` sets `"outputDirectory": "site"`,
  so only the built site is served — docs and source are not public.
- **Dependencies added:** none at runtime. Build: Pillow (already used). Tests: Playwright
  (Python). Fonts were trimmed with fontTools once; the result is committed.

## UX decisions

- **CTA hierarchy** exactly as the brief: Plan Your Trip (nav), Plan My Trek (home hero),
  Explore Trek (cards), Request a Personalised Quote / Ask Jenish a Question (trip pages),
  Continue on WhatsApp / Send via Email (form).
- **Only the name is required** in the inquiry form. Dates can be "flexible", trek can be
  "I'm not sure yet – help me choose". The message preview updates live, so people see exactly
  what will be sent.
- The status message after clicking says the message **is not sent yet** — no fake success.
- Finder recommends from verified facts only (days, difficulty, tags) and says it isn't a
  fitness or medical check.
- "Why trek with me" marks each service as **Included with every trek** or **Optional, ask when
  planning**. Only items the old site already called included are marked included.
- Prices: "Request a personalised quote" everywhere; no invented figures.

## Content changes

- Copy rewritten in Jenish's first person where it speaks for him (guide page, steps, FAQ).
- Safety: oxygen checks now "help us notice early signs of altitude sickness", with a clear
  statement that no plan removes the risk. Guide rule updated with the Khumbu exception.
- Gallery caption no longer claims every photo is by Jenish (wildlife photos unverified).

## Performance

- WebP at 480/800/1200/1800 px with `srcset`/`sizes`, JPEG fallback, width/height on every image.
- Hero image preloaded with `imagesrcset`; below-the-fold images lazy.
- Fonts trimmed to the axes in use: 290 KiB → 128 KiB; only the body font is preloaded.
- Hero text no longer fades in (it was delaying the largest paint).
- `vercel.json`: long cache for fonts and images, security headers.

## SEO / AEO / GEO

- `DOMAIN = https://somewhereinmountains.vercel.app` → canonical, og:url, og:image, sitemap,
  robots.txt. Change one line when a custom domain is added.
- Schema: TravelAgency (no invented price range), Person (Jenish), WebSite, ProfilePage,
  TouristTrip per trip, BreadcrumbList with URLs, FAQPage (FAQ page and each trip page).
- Unique titles and descriptions targeting "local trekking guide Nepal", "private trek",
  per-route queries.

## Analytics

No analytics provider was added (that would need consent decisions). `site.js` exposes a
privacy-safe hook, `smTrack(name, props)`, fired by `data-track` attributes and the forms:
`hero_plan_trip_clicked`, `explore_treks_clicked`, `trek_card_clicked`, `trek_filter_used`,
`trek_recommendation_completed`, `guide_profile_clicked`, `inquiry_form_started`,
`inquiry_whatsapp_clicked`, `inquiry_email_clicked`, `inquiry_message_copied`, and others.
Only trek IDs, filter values and page names are passed — never names, emails or messages.
It forwards to Plausible automatically if `window.plausible` exists. Recommended: Vercel Web
Analytics or Plausible (both cookieless); update the privacy policy when enabled.
